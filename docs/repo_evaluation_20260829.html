外部仓库评估：last30days-skill-cn & ai_quant_trade

评估日期：2026-08-29 · 按「可自动化 / 免费 / 与现有 LLM-native 流水线兼容」原则打分
结论摘要
建议接入 last30days-skill-cn：已有可运行的舆情/事件挖掘 CLI，适合作为盘前「主题热度」数据源，与现有产业链挖掘和盘前简报互补。
谨慎借鉴 ai_quant_trade：仓库较庞杂，整体以传统 ML/LSTM/强化学习为主，与当前 LLM-native 方法论冲突；仅热点报告生成、数据 IO 封装、基本面过滤信号引擎三个模块可参考。r>

1. last30days-skill-cn

仓库：Jesseovo/last30days-skill-cn

定位：用 LLM 抓取近 30 天微博/百度/头条/bilibili 等平台信息，生成主题事件脉络与舆情摘要。

实测结果：

  • last30days.py --diagnose 通过，依赖可用。
  • 「人形机器人产业链」「低空经济」两个主题均能在 10–30 秒内返回 compact 摘要。
  • 输出为 Markdown 文本，可直接注入盘前简报 prompt。
维度评分说明
可自动化高CLI 化，可 cron 调用
免费入口高无需 API key，依赖公开搜索
数据质量中社交媒体噪音大，需 LLM 二次过滤
与现有流水线兼容高输出文本可直接注入 supply_chain_news_context / morning brief

建议：作为盘前「主题热度/事件」补充源，接入 last30days_morning_brief.py；不替代同花顺特色数据，只做舆情侧交叉验证。

2. ai_quant_trade

仓库：charliedream1/ai_quant_trade

定位：AI + 量化交易资源集合，包含 LLM 示例、传统 ML、强化学习、回测框架、因子挖掘等。

实测结果：

  • 仓库结构松散，部分子项目无 requirements/安装说明。
  • 大量子目录依赖 LSTM/XGBoost/LightGBM/强化学习，与当前「LLM-native、拒绝硬编码阈值、优化器数据驱动」原则冲突。
  • 以下三个模块可局部借鉴：
可借鉴模块用途接入成本
egs_llm/b01_app/a01_hot_topic_report热点主题报告生成 pipeline中
quant_brain/data_io/api_stock_data.py数据接口封装思路低
vibe_trading_skills/fundamental-filter/example_signal_engine.py基本面过滤信号引擎中
维度评分说明
可自动化低缺少统一入口，需拆分适配
免费入口高开源仓库
数据质量中低依赖示例数据，生产需重写
与现有流水线兼容低传统 ML/RL 路径冲突

建议：不整体接入。仅提取热点报告生成思路，复用到 supply_chain_news_context.py 的「主题舆情日报」；基本面过滤引擎思想可用来升级 fetch_fundamentals_cache.py 的评分字段。

3. 优先级与下一步

  1. 高：把 last30days 接入盘前简报，每天早上对当日产业链主题做一次热度扫描。
  2. 中：参考 ai_quant_trade 的热点报告模板，升级现有 supply_chain_*_news.html 页面结构。
  3. 低：ai_quant_trade 的 RL/LSTM 部分不引入。
